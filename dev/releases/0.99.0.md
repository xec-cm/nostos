## Reproduce the candidate checks

Use a clean checkout of the package-content commit with development requirements
and Pandoc installed. Run from the repository root:

```sh
Rscript --vanilla dev/check-package.R
Rscript --vanilla dev/check-generated.R
Rscript --vanilla dev/coverage.R
Rscript --vanilla dev/check-bioc.R
Rscript --vanilla dev/check-installed.R check/recoverome_0.99.0.tar.gz
```

The installation helper copies README.Rmd from the checkout (it is excluded from
the tarball) and the vignette from the installed package. It renders them in a
temporary directory, checks the loaded namespace/version and removes its temporary
files. Existing libraries are preserved; it downloads neither packages nor data.

## Maintainer publication checklist

1. Review this PR, its independent review and final required `R package checks`,
   `quality`, and `Build the documentation site` results. Inspect the devel report.
2. Squash-merge when satisfied. Record the resulting commit and compare package
   inputs with the validated candidate. Package-content changes require fresh
   checks. Prefer the checked archive from the merged `devel` workflow and retain
   its identity, SHA-256 and check log before artifact expiry.
3. Decide explicitly whether to publish an experimental GitHub prerelease. If
   chosen, confirm `v0.99.0` is unused and tags the reviewed merged commit with
   DESCRIPTION version 0.99.0. No tag or release was created by this preparation.
4. Attach the checked `recoverome_0.99.0.tar.gz` and its identity/checksum; use the
   [release-note draft](0.99.0-notes.md), removing draft wording only on publication.
   Verify installation from the tag and downloaded attachment.
5. Decide separately when to submit to Bioconductor, following the readiness
   document's source-layout and maintenance steps. Refresh checks against the
   actual submission revision and current devel environment.

Only the maintainer merges, publishes or submits. Neither milestones nor this
preparation trigger those actions automatically.
